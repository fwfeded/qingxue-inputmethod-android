# 公开测试版发布前核对

目前仅准备源码快照与 unsigned release，没有创建远程仓库、正式密钥或 GitHub Release。

1. 确认 GitHub 账号、仓库名、公开内容；使用青学自己的仓库，不推上游 origin。保留 GPL、来源与可复现的对应源码。源码快照不含历史，若导入历史需另做历史扫描。
2. 人工审阅 SOURCE-MANIFEST、许可/素材和隐私说明；有限模式扫描不能证明没有任何秘密。依赖来源与构建输入哈希均需通过。
3. 确定长期签名密钥、备份与保管；旧开发签名升级到正式签名先验证数据保留。应用签名密钥与更新索引签名密钥职责不同，私钥都不上传源码。
4. 在干净源码目录执行 release 构建并实际运行 GitHub CI；确认未启调试、无预装模型、ABI/16KB 对齐、版本号递增、许可证完整。
5. 模拟器验证覆盖升级、取消/失败、个人词库与模型保留；真实手机验证键盘、语音、反馈与底部适配。公布已知问题。
6. 按批准的更新预览实施 Android 更新客户端。采用青学自己的 HTTPS 索引及公钥，不请求上游青简更新服务。校验索引签名、包 SHA-256、包名、证书与更高 versionCode；失败保留原版。
7. 用户审阅确定后，再发布对应源码标签、签名 APK、SHA-256、变更说明和签名索引。APK 放 Releases，不放源码 Git 历史；模型保持按需下载。

本仓库模板只在 workflow_dispatch 手动触发，contents:read；不含发布凭据，不自动发布。上游桌面 release 工作流不进入导出快照。
